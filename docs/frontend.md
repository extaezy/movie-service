# План frontend

## Маршруты

| Route | Страница | Доступ |
|---|---|---|
| `/` | Каталог | публичный |
| `/movies/:id` | Фильм | публичный |
| `/login` | Вход | публичный |
| `/register` | Регистрация | публичный |
| `/profile/:username` | Профиль | с privacy-ограничениями |
| `/profile/me/edit` | Редактирование профиля | авторизованный |
| `/lists/:type` | Список фильмов | авторизованный |
| `/friends` | Друзья и заявки | авторизованный |
| `/admin` | Администрирование | admin |

Страницы профиля и списков показывают только данные, разрешённые сервером для текущего пользователя. Интерфейс не заменяет серверную проверку прав.

Карточка фильма проверяет наличие фильма в каждом списке текущего пользователя через `GET /users/{username}/movies?list_type=...&page=1`. Для каждого списка проверка идёт до первого совпадения по внутреннему ID фильма или до последней страницы. Нажатие добавляет фильм в выбранный список через `POST /movies/{movie_id}/lists` или удаляет через `DELETE /movies/{movie_id}/lists/{list_type}`. Каждый список переключается независимо, его кнопка блокируется до завершения запроса, ошибка отображается рядом с кнопками. Страницы списков используют тот же запрос чтения, показывают фильмы из `results` и используют `total_pages` для навигации. При смене списка запрашивается первая страница.

Во вкладке «Просмотрено» этот же запрос принимает `q` для поиска по названию и `genre_id` для фильтра по жанру. При изменении любого из них запрашивается первая страница. Для следующих страниц передаются те же параметры поиска и жанра.

На странице фильма `UserReviewList` показывает публичные рецензии из `GET /movies/{movie_id}/reviews`, включая рецензии авторов с закрытыми профилями. В закрытом профиле вкладки рецензий, оценок и списков фильмов доступны владельцу и подтверждённым друзьям. Для остальных посетителей показываются `username`, аватар и уведомление о закрытом профиле.

`UserReviewList` загружает `results` первой страницы рецензий. Пока `page` меньше `total_pages`, кнопка «Показать ещё» запрашивает следующую страницу и добавляет её рецензии к уже показанным.

Главная загружает витрину через `GET /movies/discover`. Параметры витрины: `page`, `tmdb_genre_id`, `year`, `sort`. При изменении фильтра или сортировки frontend запрашивает первую страницу. Поиск по названию вызывает `GET /movies/search?q=...&page=...`.

Вкладка «В каталоге» (`/?catalog=local`) загружает сохранённые фильмы через `GET /movies`. Она передаёт `page`, необязательный `year` и сортировку по дате релиза `sort`. При изменении года или сортировки загрузка начинается с первой страницы. Ссылка на фильм открывает `/movies/:id` по внутреннему ID.

При выборе фильма из витрины или поиска frontend вызывает `GET /movies/tmdb/{tmdb_id}`, затем открывает `/movies/:id` с внутренним `id` полученной карточки. Прямая ссылка `/movies/:id` загружает `GET /movies/{id}`. Пока карточка загружается, отображается loading; при 404 — фильм не найден, при 502/503 — ошибка с повтором запроса. Для запросов оценок и списков используется внутренний ID карточки.

Авторизованный пользователь может поставить или изменить оценку через `PUT /movies/{movie_id}/rating` и удалить её через `DELETE /movies/{movie_id}/rating`. После успешного запроса карточка обновляет общий рейтинг и число голосов через `GET /movies/{movie_id}`. Личная оценка подсвечивается после сохранения на открытой карточке. После перезагрузки оценку можно изменить или удалить, но подсветка сбрасывается, поскольку API карточки возвращает только агрегат.

## Компоненты

`AppLayout`, `Header`, `SearchBar`, `MovieCard`, `MovieGrid`, `MovieFilters`, `Pagination`, `MovieHero`, `RatingSummary`, `CriticReviewList`, `UserReviewList`, `ProfileHeader`, `ProfileTabs`, `PrivacyNotice`, `AuthForm`, `ProfileForm`, `RatingForm`, `ReviewForm`, `FriendRequestList`, `FriendButton`, `AdminSyncPanel`.

## Состояния

Каждая страница должна иметь `loading`, `success`, `empty`, `error`. Для мутаций кнопка блокируется на время запроса и показывает ошибку.

При отказе запроса интерфейс показывает понятное сообщение. Типы запросов и ответов должны соответствовать `docs/api.md`.

## Клиентская модель

- `AuthContext`: текущий пользователь, вход, выход, загрузка;
- `apiClient`: Axios с базовым URL и обработкой `401`;
- feature-модули `auth`, `movies`, `users`, `lists`, `reviews`, `friends`, `admin`;
- TypeScript-типы должны соответствовать `docs/api.md`.

## Wireframes

### Каталог

```text
[Logo] [Поиск........................] [Войти]
[Жанр v] [Год v] [Сортировка v]
[ MovieCard ][ MovieCard ][ MovieCard ]
[ MovieCard ][ MovieCard ][ MovieCard ]
                 [pagination]
```

### Фильм

```text
[Постер] [Название, дата, жанры]
         [описание]
         [Оценить] [Хочу посмотреть] [Просмотрено] [Избранное]
[Оценка пользователей Movie Service и число оценок] [Рейтинг критиков]
[Рецензии критиков] [Рецензии пользователей]
```

### Профиль

```text
[Аватар] [Имя] [описание] [Добавить в друзья]
[Рецензии] [Оценки] [Хочу посмотреть] [Просмотрено] [Избранное]
```
