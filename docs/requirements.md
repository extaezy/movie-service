# Спецификация требований к ПО "Movie Service" (v1.0)

## 1. Введение

**Цель документа:** Определение исчерпывающего набора функциональных требований, бизнес-правил и нефункциональных требований к MVP веб-сервиса для управления кинопросмотрами.

**Область применения:** Документ является единым источником истины (Single Source of Truth) для команды разработки и используется аналитиком, архитектором, backend/frontend-разработчиками, тестировщиком и техническим писателем.

**Ограничения MVP:** Первая версия предназначена для работы на русском языке и локального запуска. В неё входят только функции, перечисленные ниже.

## 2. Глоссарий

| Термин | Определение |
| :--- | :--- |
| **TMDB** | The Movie Database — внешний источник данных о фильмах, используемый для каталога. |
| **MVP** | Минимально жизнеспособный продукт (первая версия сервиса). |
| **Нормализованный ID дружбы** | Правило хранения связи: в записи о дружбе `user_low_id` всегда строго меньше `user_high_id`. |
| **Агрегат оценки** | Суммарный/средний рейтинг фильма, рассчитываемый по всем пользовательским оценкам. |
| **Мутация** | Любая операция, изменяющая состояние системы. |

## 3. Бизнес-требования (Business Requirements, BR)

| ID | Описание | Обоснование |
| :--- | :--- | :--- |
| **BR.01** | Предоставить пользователям единый каталог фильмов с возможностью поиска и фильтрации. | Удовлетворение потребности в поиске кино для просмотра. |
| **BR.02** | Обеспечить механизм сбора и отображения пользовательских оценок и рецензий. | Формирование социального доказательства и сообщества вокруг фильмов. |
| **BR.03** | Реализовать систему социальных связей (друзья) с гибким контролем приватности. | Баланс между социальным взаимодействием и защитой персональных данных. |
| **BR.04** | Интегрировать профессиональные рецензии критиков для сравнения мнений. | Повышение ценности контента за счет экспертных оценок. |

## 4. Функциональные требования (Functional Requirements, FR)

*Каждое требование атомарно, не содержит привязки к конкретным URL/HTTP-методам и проверяемо.*

### 4.1. Аутентификация и управление пользователями (AUTH / USER)

- **FR.AUTH.01**: Система должна позволять новому пользователю зарегистрироваться, указав уникальный email, username и пароль.
- **FR.AUTH.02**: Система должна позволять зарегистрированному пользователю войти в систему, указав email и пароль, и получить сессионный токен для последующих запросов.
- **FR.AUTH.03**: Система должна позволять авторизованному пользователю завершить сессию (выйти из системы), после чего сессионный токен становится недействительным.
- **FR.USER.01**: Система должна позволять авторизованному пользователю просматривать данные своего профиля.
- **FR.USER.02**: Система должна позволять авторизованному пользователю изменять отображаемое имя, описание профиля, URL аватара и режим приватности (открытый/закрытый).
- **FR.USER.03**: Система должна возвращать только базовую информацию (username, аватар) при просмотре профиля с режимом приватности «закрытый», если просматривающий не является подтверждённым другом владельца.

### 4.2. Каталог фильмов (MOVIES)

- **FR.MOV.01**: Система должна предоставлять возможность просмотра списка фильмов с постраничной навигацией.
- **FR.MOV.02**: Система должна позволять фильтровать список фильмов по жанру и году выпуска.
- **FR.MOV.03**: Система должна позволять сортировать список фильмов (по дате выхода, по рейтингу и т.д.).
- **FR.MOV.04**: Система должна позволять выполнять полнотекстовый поиск фильмов по названию.
- **FR.MOV.05**: Система должна отображать детальную информацию о фильме: постер, описание, дата выхода, жанры и длительность.

### 4.3. Пользовательский контент: Списки, Оценки, Рецензии (CONTENT)

- **FR.CNT.01**: Система должна позволять авторизованному пользователю добавить фильм в один из трёх списков: «планирую посмотреть» (watchlist), «просмотрено» (watched), «любимое» (favorite).
- **FR.CNT.02**: Система должна позволять авторизованному пользователю удалить фильм из конкретного списка.
- **FR.CNT.03**: Система должна позволять авторизованному пользователю выставить фильму числовую оценку.
- **FR.CNT.04**: Система должна принимать только целочисленные оценки в диапазоне от 1 до 10 включительно.
- **FR.CNT.05**: Система должна позволять авторизованному пользователю удалить ранее выставленную оценку фильму.
- **FR.CNT.06**: Система должна позволять авторизованному пользователю написать текстовую рецензию на фильм.
- **FR.CNT.07**: Система должна позволять автору рецензии отметить, содержит ли рецензия спойлеры.
- **FR.CNT.08**: Система должна позволять автору рецензии изменить текст и флаг спойлеров в уже опубликованной рецензии.
- **FR.CNT.09**: Система должна позволять автору рецензии удалить свою рецензию.

### 4.4. Социальные взаимодействия (FRIENDS)

- **FR.FRD.01**: Система должна позволять авторизованному пользователю отправить заявку в друзья другому пользователю.
- **FR.FRD.02**: Система должна позволять авторизованному пользователю просмотреть список входящих заявок в друзья.
- **FR.FRD.03**: Система должна позволять пользователю принять входящую заявку в друзья.
- **FR.FRD.04**: Система должна позволять пользователю отклонить входящую заявку в друзья.
- **FR.FRD.05**: Система должна позволять пользователю удалить подтверждённого друга из своего списка.
- **FR.FRD.06**: Система должна позволять пользователю просмотреть список своих подтверждённых друзей.

### 4.5. Рецензии критиков и администрирование (ADMIN / CRITIC)

- **FR.ADM.01**: Система должна позволять пользователю с ролью администратора запустить синхронизацию каталога фильмов с внешним источником (TMDB).
- **FR.CRT.01**: Система должна отображать список профессиональных рецензий критиков для выбранного фильма.
- **FR.CRT.02**: Система должна позволять администратору вручную добавить рецензию критика (указать источник, критика, язык, выдержку, ссылку, оценку и вердикт).
- **FR.CRT.03**: Система должна позволять администратору удалить рецензию критика.
- **FR.CRT.04**: Система должна позволять администратору импортировать рецензии критиков из внешнего источника массово.

## 5. Бизнес-правила (Business Rules, BRules)

*Ограничения предметной области, которые система должна соблюдать при обработке данных.*

### 5.1. Правила целостности каталога фильмов

- **BRULE.MOV.01**: Каждый фильм в каталоге должен иметь уникальный идентификатор внешнего источника (`tmdb_id`).
- **BRULE.MOV.02**: Фильм может быть связан с несколькими жанрами, но каждая связь «фильм–жанр» должна быть уникальной.

### 5.2. Правила пользовательского контента

- **BRULE.CNT.01**: Пользователь может выставить фильму не более одной оценки.
- **BRULE.CNT.02**: Пользователь может написать не более одной рецензии на фильм.
- **BRULE.CNT.03**: Пользователь может добавить фильм в каждый тип списка (`watchlist`, `watched`, `favorite`) не более одного раза.
- **BRULE.CNT.04**: Оценка фильма должна быть целым числом в диапазоне от 1 до 10 включительно.

### 5.3. Правила социальных взаимодействий

- **BRULE.FRD.01**: Между двумя пользователями может существовать не более одной связи дружбы.
- **BRULE.FRD.02**: Связь дружбы должна хранить идентификаторы пользователей в нормализованном порядке: `user_low_id` строго меньше `user_high_id`.
- **BRULE.FRD.03**: Связь дружбы может находиться только в одном из трёх состояний: `pending` (ожидает подтверждения), `accepted` (подтверждена), `rejected` (отклонена).
- **BRULE.FRD.04**: Заявку в друзья может отправить только пользователь, который ещё не находится в списке друзей или pending-заявок с целевым пользователем.

### 5.4. Правила рецензий критиков

- **BRULE.CRT.01**: Каждая рецензия критика должна быть уникальной по внешнему идентификатору (`external_id`) или внешнему URL (`external_url`).
- **BRULE.CRT.02**: Рецензия критика должна содержать ссылку на источник публикации.
- **BRULE.CRT.03**: Рецензия критика должна хранить как исходную оценку (в шкале источника), так и нормализованную оценку (приведённую к единой шкале).

## 6. Нефункциональные требования (Non-Functional Requirements, NFR)

*Характеристики качества системы: как она должна работать, а не что делать.*

### 6.1. Безопасность (SEC)

- **NFR.SEC.01**: Система должна хранить пароли пользователей только в виде криптографических хэшей с использованием современного алгоритма (например, bcrypt или argon2).
- **NFR.SEC.02**: Система должна проверять права доступа перед выполнением любой операции изменения данных. При отсутствии прав система должна возвращать ошибку авторизации.
- **NFR.SEC.03**: Система не должна раскрывать метаданные (факт существования) скрытых списков и рецензий закрытого профиля для посторонних пользователей.
- **NFR.SEC.04**: Система должна включать оценку пользователя с закрытым профилем в агрегированный рейтинг фильма без возможности идентификации автора.
- **NFR.SEC.05**: Система должна хранить ключи внешних API (TMDB) и учётные данные базы данных исключительно в переменных окружения сервера, не передавая их клиентской части.

### 6.2. Производительность (PERF)

- **NFR.PERF.01**: Система должна возвращать ответ на запрос списка фильмов (с пагинацией) не более чем за 500 мс при нагрузке до 100 одновременных пользователей.
- **NFR.PERF.02**: Система должна возвращать ответ на запрос детальной информации о фильме не более чем за 300 мс.
- **NFR.PERF.03**: Система должна поддерживать одновременную работу до 100 активных пользователей без деградации производительности.

### 6.3. Надёжность и доступность (REL)

- **NFR.REL.01**: Система должна корректно обрабатывать недоступность внешнего источника (TMDB), возвращая понятное сообщение об ошибке вместо падения сервиса.
- **NFR.REL.02**: Система должна сохранять работоспособность при временной недоступности базы данных, возвращая ошибку 503 (Service Unavailable) и автоматически восстанавливая работу после восстановления БД.

### 6.4. Архитектура и развёртывание (ARCH / DEP)

- **NFR.ARCH.01**: Клиентская часть (React) должна взаимодействовать исключительно с Backend (FastAPI) через REST API. Прямые запросы к БД или внешним API из браузера запрещены.
- **NFR.DEP.01**: Локальное окружение должно разворачиваться единой командой через `docker-compose.yml`.
- **NFR.DEP.02**: Порт базы данных PostgreSQL (5432) не должен быть доступен с хост-машины; доступ разрешён только изнутри Docker-сети.
- **NFR.DEP.03**: Исходящие запросы к внешнему источнику (TMDB) должны выполняться строго по протоколу HTTPS.

### 6.5. Сопровождаемость (MAINT)

- **NFR.MAINT.01**: Система должна использовать миграции базы данных (Alembic) для управления изменениями схемы БД.
- **NFR.MAINT.02**: Система должна покрывать критические бизнес-сценарии автоматическими тестами (unit и integration) с покрытием не менее 70%.

## 7. Исключения из области действия (Out of Scope для MVP)

Система **НЕ ДОЛЖНА** реализовывать в версии 1.0:
- поддержку сериалов;
- мобильные приложения;
- чаты и realtime-уведомления (WebSocket);
- OAuth-авторизацию;
- восстановление пароля через email;
- машинный перевод;
- автоматический анализ тональности;
- лайки и комментарии к рецензиям;
- парсинг (scraping) сайтов без официального API;
- публичный production-сервер.
