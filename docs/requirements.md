# Спецификация требований к ПО "Movie Service" (v1.0)

## 1. Введение

**Цель документа:** Определение исчерпывающего набора функциональных и нефункциональных требований к MVP веб-сервиса для управления кинопросмотрами.

**Область применения:** Документ является единым источником истины (Single Source of Truth) для команды разработки и используется аналитиком, архитектором, backend/frontend-разработчиками, тестировщиком и техническим писателем.

**Ограничения MVP:** Первая версия предназначена для работы на русском языке и локального запуска. В неё входят только функции, перечисленные ниже.

## 2. Глоссарий

| Термин | Определение |
| :--- | :--- |
| **TMDB** | The Movie Database — внешний источник данных о фильмах, используемый для каталога. |
| **MVP** | Минимально жизнеспособный продукт (первая версия сервиса). |
| **Нормализованный ID дружбы** | Правило хранения связи: в записи о дружбе `user_low_id` всегда строго меньше `user_high_id`. |
| **Агрегат оценки** | Суммарный/средний рейтинг фильма, рассчитываемый по всем пользовательским оценкам. |
| **Мутация** | Любой запрос, изменяющий состояние системы: `POST`, `PUT`, `PATCH`, `DELETE`. |

## 3. Бизнес-требования (Business Requirements, BR)

| ID | Описание | Обоснование |
| :--- | :--- | :--- |
| **BR.01** | Предоставить пользователям единый каталог фильмов с возможностью поиска и фильтрации. | Удовлетворение потребности в поиске кино для просмотра. |
| **BR.02** | Обеспечить механизм сбора и отображения пользовательских оценок и рецензий. | Формирование социального доказательства и сообщества вокруг фильмов. |
| **BR.03** | Реализовать систему социальных связей (друзья) с гибким контролем приватности. | Баланс между социальным взаимодействием и защитой персональных данных. |
| **BR.04** | Интегрировать профессиональные рецензии критиков для сравнения мнений. | Повышение ценности контента за счет экспертных оценок. |

## 4. Функциональные требования (Functional Requirements, FR)

*Каждое требование атомарно и проверяемо.*

### 4.1. Аутентификация и управление пользователями (AUTH / USER)

- **FR.AUTH.01**: Система должна предоставлять endpoint `POST /auth/register` для создания нового пользователя с уникальными `email` и `username`.
- **FR.AUTH.02**: Система должна предоставлять endpoint `POST /auth/login` для аутентификации пользователя по email и паролю с возвратом сессионного токена.
- **FR.AUTH.03**: Система должна предоставлять endpoint `POST /auth/logout` для аннулирования сессии текущего пользователя.
- **FR.USER.01**: Система должна позволять авторизованному пользователю получать данные своего профиля через `GET /auth/me`.
- **FR.USER.02**: Система должна позволять авторизованному пользователю обновлять поля `display_name`, `bio`, `avatar_url` и `is_private` через `PATCH /users/me/profile`.
- **FR.USER.03**: Система должна возвращать только базовую информацию при запросе `GET /users/{username}` профиля с `is_private=true`, если запрашивающий не является другом владельца.

### 4.2. Каталог фильмов (MOVIES)

- **FR.MOV.01**: Система должна предоставлять пагинированный список фильмов через `GET /movies` с параметрами `page`, `page_size`, `genre_id`, `year`, `sort`.
- **FR.MOV.02**: Система должна предоставлять полнотекстовый поиск фильмов через `GET /movies/search?q={query}`.
- **FR.MOV.03**: Система должна возвращать детальные данные фильма (постер, описание, дата выхода, жанры, длительность) через `GET /movies/{movie_id}`.

### 4.3. Пользовательский контент: Списки, Оценки, Рецензии (CONTENT)

- **FR.CNT.01**: Система должна позволять добавлять фильм в список (`watchlist`, `watched`, `favorite`) через `POST /movies/{movie_id}/lists`.
- **FR.CNT.02**: Система должна позволять удалять фильм из конкретного списка через `DELETE /movies/{movie_id}/lists/{list_type}`.
- **FR.CNT.03**: Система должна позволять устанавливать оценку фильму (целое число) через `PUT /movies/{movie_id}/rating`.
- **FR.CNT.04**: Система должна отклонять запрос на установку оценки, если значение `score` не является целым числом в диапазоне от 1 до 10 (возврат HTTP 422).
- **FR.CNT.05**: Система должна позволять удалять оценку фильма через `DELETE /movies/{movie_id}/rating`.
- **FR.CNT.06**: Система должна позволять создавать рецензию с текстом и флагом `contains_spoilers` через `POST /movies/{movie_id}/reviews`.
- **FR.CNT.07**: Система должна позволять автору изменять свою рецензию через `PATCH /reviews/{review_id}`.
- **FR.CNT.08**: Система должна позволять автору удалять свою рецензию через `DELETE /reviews/{review_id}`.

### 4.4. Социальные взаимодействия (FRIENDS)

- **FR.FRD.01**: Система должна позволять отправлять заявку в друзья через `POST /friends/requests/{user_id}`.
- **FR.FRD.02**: Система должна позволять просматривать входящие заявки через `GET /friends/requests`.
- **FR.FRD.03**: Система должна позволять принимать заявку через `POST /friends/requests/{request_id}/accept`.
- **FR.FRD.04**: Система должна позволять отклонять заявку через `POST /friends/requests/{request_id}/reject`.
- **FR.FRD.05**: Система должна позволять удалять пользователя из списка друзей через `DELETE /friends/{user_id}`.
- **FR.FRD.06**: Система должна позволять получать список утверждённых друзей через `GET /friends`.

### 4.5. Рецензии критиков и администрирование (ADMIN / CRITIC)

- **FR.ADM.01**: Система должна позволять администратору запускать синхронизацию каталога с TMDB через `POST /admin/movies/sync`.
- **FR.CRT.01**: Система должна возвращать список рецензий критиков для фильма через `GET /movies/{movie_id}/critic-reviews?language=ru`.
- **FR.CRT.02**: Система должна позволять администратору вручную создавать рецензию критика через `POST /admin/critic-reviews`.
- **FR.CRT.03**: Система должна позволять администратору удалять рецензию критика через `DELETE /admin/critic-reviews/{review_id}`.

## 5. Нефункциональные требования (Non-Functional Requirements, NFR)

### 5.1. Безопасность и контроль доступа (SEC)

- **NFR.SEC.01**: Система должна хранить пароли пользователей только в виде криптографических хэшей (поле `password_hash`).
- **NFR.SEC.02**: Система должна проверять права доступа перед выполнением любой мутации. При отсутствии прав возвращается HTTP 403.
- **NFR.SEC.03**: Система должна скрывать факт существования скрытых списков и рецензий закрытого профиля для посторонних пользователей (возврат HTTP 404 или 403 с кодом ошибки `PRIVATE_PROFILE`, без раскрытия метаданных).
- **NFR.SEC.04**: Система должна включать оценку пользователя с закрытым профилем в агрегированный рейтинг фильма, но без возможности идентификации автора этой оценки.
- **NFR.SEC.05**: Система должна хранить ключи внешних API (TMDB) исключительно в переменных окружения сервера.

### 5.2. Целостность данных (DATA)

- **NFR.DATA.01**: Система должна гарантировать уникальность `tmdb_id` в таблице `MOVIES`.
- **NFR.DATA.02**: Система должна гарантировать наличие не более одной записи оценки (`RATINGS`) на уникальную пару `(user_id, movie_id)`.
- **NFR.DATA.03**: Система должна гарантировать наличие не более одной пользовательской рецензии (`USER_REVIEWS`) на уникальную пару `(user_id, movie_id)`.
- **NFR.DATA.04**: Система должна хранить связь дружбы одной записью, где `user_low_id` строго меньше `user_high_id`, обеспечивая уникальность пары.
- **NFR.DATA.05**: Система должна поддерживать только три статуса дружбы: `pending`, `accepted`, `rejected`.

### 5.3. Архитектура и развёртывание (ARCH / DEP)

- **NFR.ARCH.01**: Клиентская часть (React) должна взаимодействовать исключительно с Backend (FastAPI) через REST API. Прямые запросы к БД или внешним API из браузера запрещены.
- **NFR.DEP.01**: Локальное окружение должно разворачиваться единой командой через `docker-compose.yml`.
- **NFR.DEP.02**: Порт базы данных PostgreSQL (5432) не должен быть проброшен (exposed) на хост-машину, доступ разрешён только внутри Docker-сети.
- **NFR.DEP.03**: Исходящие запросы к TMDB должны выполняться строго по протоколу HTTPS (порт 443).

### 5.4. Исключения из области действия (Out of Scope для MVP)

Система **НЕ ДОЛЖНА** реализовывать в версии 1.0:
- поддержку сериалов;
- мобильные приложения;
- чаты и realtime-уведомления (WebSocket);
- OAuth-авторизацию;
- восстановление пароля через email;
- машинный перевод;
- автоматический анализ тональности;
- лайки и комментарии к рецензиям;
- парсинг (scraping) сайтов без официального API;
- публичный production-сервер.
