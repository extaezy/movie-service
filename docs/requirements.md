# Спецификация требований к ПО "Movie Service" (v1.0)

## 1. Введение

**Цель документа:** Определение исчерпывающего набора функциональных требований, бизнес-правил и нефункциональных требований к MVP веб-сервиса для управления кинопросмотрами.

**Область применения:** Документ является единым источником истины (Single Source of Truth) для команды разработки и используется аналитиком, архитектором, backend/frontend-разработчиками, тестировщиком и техническим писателем.

**Ограничения MVP:** Первая версия предназначена для работы на русском языке и локального запуска. В неё входят только функции, перечисленные ниже.

## 2. Глоссарий

| Термин | Определение |
| :--- | :--- |
| **TMDB** | The Movie Database — внешний источник данных о фильмах, используемый для каталога. |
| **MVP** | Минимально жизнеспособный продукт (первая версия сервиса). |
| **Нормализованный ID дружбы** | Правило хранения связи: в записи о дружбе `user_low_id` всегда строго меньше `user_high_id`. |
| **Агрегат оценки** | Суммарный/средний рейтинг фильма, рассчитываемый по всем пользовательским оценкам. |
| **Мутация** | Любая операция, изменяющая состояние системы. |

## 3. Бизнес-требования (Business Requirements, BR)

| ID | Описание | Обоснование |
| :--- | :--- | :--- |
| **BR.01** | Предоставить пользователям единый каталог фильмов с возможностью поиска и фильтрации. | Удовлетворение потребности в поиске кино для просмотра. |
| **BR.02** | Обеспечить механизм сбора и отображения пользовательских оценок и рецензий. | Формирование социального доказательства и сообщества вокруг фильмов. |
| **BR.03** | Реализовать систему социальных связей (друзья) с гибким контролем приватности. | Баланс между социальным взаимодействием и защитой персональных данных. |
| **BR.04** | Интегрировать профессиональные рецензии критиков для сравнения мнений. | Повышение ценности контента за счет экспертных оценок. |

## 4. Функциональные требования (Functional Requirements, FR)

### 4.1. Аутентификация и управление пользователями (AUTH / USER)

- **FR.AUTH.01**: Система должна позволять незарегистрированному пользователю создать учётную запись, указав email, username и пароль.
- **FR.AUTH.02**: Система должна отклонять регистрацию, если указанный email или username уже используется другой учётной записью.
- **FR.AUTH.03**: Система должна позволять зарегистрированному пользователю войти в систему, указав email и пароль.
- **FR.AUTH.04**: Система должна выдавать пользователю токен доступа после успешной аутентификации.
- **FR.AUTH.05**: Система должна позволять авторизованному пользователю завершить текущую сессию, обеспечивая недействительность связанного с ней токена доступа.
- **FR.USER.01**: Система должна позволять авторизованному пользователю просматривать данные собственного профиля.
- **FR.USER.02**: Система должна позволять авторизованному пользователю изменять отображаемое имя, описание профиля и URL аватара.
- **FR.USER.03**: Система должна позволять авторизованному пользователю изменять режим приватности собственного профиля между состояниями «открытый» и «закрытый».
- **FR.USER.04**: Система должна позволять пользователю просматривать общедоступную информацию открытого профиля.
- **FR.USER.05**: Система должна отображать только username и аватар при просмотре закрытого профиля пользователем, который не является его владельцем или подтверждённым другом.
- **FR.USER.06**: Система должна предоставлять подтверждённым друзьям владельца закрытого профиля доступ к информации, разрешённой для друзей.

### 4.2. Каталог фильмов (MOV)

- **FR.MOV.01**: Система должна предоставлять пользователю возможность просматривать каталог фильмов с постраничной навигацией.
- **FR.MOV.02**: Система должна позволять пользователю фильтровать каталог фильмов по жанру и году выпуска.
- **FR.MOV.03**: Система должна позволять пользователю сортировать фильмы по дате выхода и рейтингу в порядке возрастания и убывания.
- **FR.MOV.04**: Система должна позволять пользователю выполнять поиск фильмов по названию.
- **FR.MOV.05**: Система должна предоставлять пользователю возможность просматривать подробную информацию о фильме, включая постер, описание, дату выхода, жанры и длительность.

### 4.3. Пользовательский контент: списки, оценки, рецензии (CONTENT)

- **FR.CNT.01**: Система должна позволять авторизованному пользователю добавлять фильмы в списки «Планирую посмотреть» (watchlist), «Просмотрено» (watched) и «Любимое» (favorite).
- **FR.CNT.02**: Система должна позволять авторизованному пользователю удалять фильмы из собственных списков.
- **FR.CNT.03**: Система должна позволять авторизованному пользователю выставлять числовую оценку фильму.
- **FR.CNT.04**: Система должна принимать только целочисленные оценки в диапазоне от 1 до 10 включительно.
- **FR.CNT.05**: Система должна позволять авторизованному пользователю изменять ранее выставленную оценку фильму.
- **FR.CNT.06**: Система должна позволять авторизованному пользователю удалять ранее выставленную оценку фильму.
- **FR.CNT.07**: Система должна позволять авторизованному пользователю публиковать текстовую рецензию на фильм.
- **FR.CNT.08**: Система должна позволять автору рецензии указывать наличие спойлеров при её публикации.
- **FR.CNT.09**: Система должна позволять автору рецензии изменять текст и признак наличия спойлеров в опубликованной рецензии.
- **FR.CNT.10**: Система должна позволять автору рецензии удалять собственную рецензию.

### 4.4. Социальные взаимодействия (FRIENDS)

- **FR.FRD.01**: Система должна позволять авторизованному пользователю отправить заявку в друзья другому пользователю.
- **FR.FRD.02**: Система должна позволять авторизованному пользователю просмотреть список входящих заявок в друзья.
- **FR.FRD.03**: Система должна позволять пользователю принять входящую заявку в друзья.
- **FR.FRD.04**: Система должна позволять пользователю отклонить входящую заявку в друзья.
- **FR.FRD.05**: Система должна позволять пользователю удалить подтверждённого друга из своего списка.
- **FR.FRD.06**: Система должна позволять пользователю просмотреть список своих подтверждённых друзей.

### 4.5. Рецензии критиков и администрирование (ADMIN / CRITIC)

- **FR.ADM.01**: Система должна позволять пользователю с ролью администратора запустить синхронизацию каталога фильмов с внешним источником (TMDB).
- **FR.CRT.01**: Система должна отображать список профессиональных рецензий критиков для выбранного фильма.
- **FR.CRT.02**: Система должна позволять администратору вручную добавить рецензию критика (указать источник, критика, язык, выдержку, ссылку, оценку и вердикт).
- **FR.CRT.03**: Система должна позволять администратору удалить рецензию критика.
- **FR.CRT.04**: Система должна позволять администратору импортировать рецензии критиков из внешнего источника массово.

## 5. Бизнес-правила (Business Rules, BRules)

### 5.1. Правила целостности каталога фильмов

- **BRULE.MOV.01**: Каждый фильм в каталоге должен иметь уникальный идентификатор внешнего источника (`tmdb_id`).
- **BRULE.MOV.02**: Фильм может быть связан с несколькими жанрами, но связь с одним и тем же жанром не должна дублироваться.

### 5.2. Правила пользовательского контента

- **BRULE.CNT.01**: Один пользователь может иметь не более одной актуальной оценки для каждого фильма.
- **BRULE.CNT.02**: При изменении оценки новое значение должно заменять ранее установленное без создания дополнительной оценки.
- **BRULE.CNT.03**: Один пользователь может иметь не более одной рецензии для каждого фильма.
- **BRULE.CNT.04**: При редактировании рецензии её текст и признак наличия спойлеров должны обновляться без создания дополнительной рецензии.
- **BRULE.CNT.05**: Один фильм может одновременно находиться в нескольких списках одного пользователя: `watchlist`, `watched`, `favorite`.
- **BRULE.CNT.06**: Один пользователь может добавить фильм в каждый тип списка не более одного раза.
- **BRULE.CNT.07**: Оценка фильма должна быть целым числом в диапазоне от 1 до 10 включительно.

### 5.3. Правила социальных взаимодействий

- **BRULE.FRD.01**: Между двумя пользователями может существовать не более одной связи дружбы.
- **BRULE.FRD.02**: Пользователь не может отправить заявку в друзья самому себе.
- **BRULE.FRD.03**: Связь дружбы может находиться только в одном из трёх состояний: `pending` (ожидает подтверждения), `accepted` (подтверждена), `rejected` (отклонена).
- **BRULE.FRD.04**: Пользователь не может отправить новую заявку в друзья, если между ним и получателем уже существует подтверждённая дружба или ожидающая рассмотрения заявка.

### 5.4. Правила рецензий критиков

- **BRULE.CRT.01**: Каждая рецензия критика должна иметь уникальную ссылку на исходную публикацию (`external_url`).
- **BRULE.CRT.02**: Каждая рецензия критика должна содержать ссылку на источник публикации.
- **BRULE.CRT.03**: При наличии числовой оценки в источнике система должна сохранять исходную оценку и её нормализованное значение, приведённое к единой шкале.

## 6. Нефункциональные требования (Non-Functional Requirements, NFR)

### 6.1. Безопасность (SEC)

- **NFR.SEC.01**: Система должна хранить пароли пользователей исключительно в виде криптографических хэшей, полученных с использованием алгоритма Argon2id.
- **NFR.SEC.02**: Система должна проверять аутентификацию и права доступа перед выполнением операций, требующих авторизации. При отсутствии необходимых прав доступ должен быть запрещён.
- **NFR.SEC.03**: Система не должна раскрывать посторонним пользователям информацию о содержимом и существовании скрытых списков и рецензий закрытых профилей.
- **NFR.SEC.04**: Система должна хранить ключи внешних API, учётные данные базы данных и секреты авторизации вне исходного кода и не передавать их клиентской части.
- **NFR.SEC.05**: Система должна ограничивать срок действия токенов доступа и отклонять запросы с недействительными или просроченными токенами.

### 6.2. Производительность (PERF)

- **NFR.PERF.01**: Время ответа на 95% запросов получения списка фильмов с пагинацией не должно превышать 500 мс при 100 одновременных виртуальных пользователях.
- **NFR.PERF.02**: Время ответа на 95% запросов получения подробной информации о фильме не должно превышать 300 мс при аналогичной нагрузке.
- **NFR.PERF.03**: Система должна обеспечивать выполнение требований NFR.PERF.01 и NFR.PERF.02 при объёме каталога до 10 000 фильмов.

### 6.3. Надёжность и доступность (REL)

- **NFR.REL.01**: При временной недоступности внешнего источника TMDB система должна сохранять работоспособность функций, не требующих обращения к данному источнику.
- **NFR.REL.02**: При недоступности PostgreSQL система должна корректно обрабатывать зависимые от базы данных запросы, возвращая ошибку HTTP 503 (Service Unavailable) без аварийного завершения приложения.
- **NFR.REL.03**: После восстановления подключения к PostgreSQL система должна возобновлять обработку запросов без ручного перезапуска приложения.
- **NFR.REL.04**: Данные PostgreSQL должны сохраняться в постоянном Docker volume, не удаляемом при пересоздании контейнера базы данных.

### 6.4. Архитектура и развёртывание (ARCH / DEP)

- **NFR.ARCH.01**: Клиентская часть (React) должна взаимодействовать с серверной частью (FastAPI) посредством REST API без прямого доступа к PostgreSQL.
- **NFR.ARCH.02**: Обращения к внешнему API TMDB должны выполняться серверной частью приложения.
- **NFR.DEP.01**: Система должна поддерживать развёртывание всех основных компонентов приложения с использованием Docker Compose.
- **NFR.DEP.02**: В окружении развёрнутого сервиса PostgreSQL должна быть доступна только через внутреннюю Docker-сеть без публикации порта на хост-машине.
- **NFR.DEP.03**: В окружении локальной разработки допускается публикация порта PostgreSQL исключительно на интерфейсе 127.0.0.1.
- **NFR.DEP.04**: Все обращения серверной части к внешнему API TMDB должны выполняться по протоколу HTTPS.

### 6.5. Сопровождаемость (MAINT)

- **NFR.MAINT.01**: Изменения схемы базы данных должны выполняться с использованием версионируемых миграций Alembic.
- **NFR.MAINT.02**: Критические бизнес-сценарии системы должны проверяться автоматизированными модульными и интеграционными тестами.
- **NFR.MAINT.03**: Покрытие серверного кода автоматизированными тестами должно составлять не менее 70% строк кода.
- **NFR.MAINT.04**: Серверная часть должна регистрировать ошибки приложения и обращения к внешним сервисам с указанием времени, уровня ошибки и её описания.

## 7. Исключения из области действия (Out of Scope для MVP)

Система **НЕ ДОЛЖНА** реализовывать в версии 1.0:
- поддержку сериалов;
- мобильные приложения;
- чаты и realtime-уведомления (WebSocket);
- OAuth-авторизацию;
- восстановление пароля через email;
- машинный перевод;
- автоматический анализ тональности;
- лайки и комментарии к рецензиям;
- парсинг (scraping) сайтов без официального API;
- публичный production-сервер.
