# BR-AUTH-001 — Чувствительные данные в ошибке регистрации

| Поле | Значение |
|---|---|
| Статус | Дефект не воспроизводится в проверяемых вариантах регистрации |
| Компонент | `POST /auth/register`, обработка ошибок валидации |
| Требование | Безопасный состав `422` в [API-контракте](../../api.md#текущий-этап-postgresql-и-access-jwt) |
| Автотест | `test_registration_validation_errors_do_not_expose_input` в [тестах PostgreSQL](../../../backend/tests/test_postgres_integration.py) |

## Суть проблемы

Поле `input` в ошибке валидации может повторять тело запроса, включая пароль и подтверждение. Контракт регистрации требует исключать переданные значения из ответа.

## Проверка

В отдельной тестовой PostgreSQL отсутствует пользователь с указанным email. Отправить запрос без username:

```json
{
  "email": "qa.required@example.com",
  "password": "testing-password-123",
  "password_confirm": "testing-password-123"
}
```

Ожидаемый и подтверждаемый автоматизацией результат:

- Статус `422`, непустой массив `detail`.
- Ошибка обязательного username содержит `loc=["body", "username"]` и `type=missing`.
- Каждая ошибка содержит только `loc`, `msg`, `type`.
- Значения пароля, подтверждения и вложенных объектов отсутствуют в ответе.
- Пользователь и профиль не создаются.

Обработчик ошибок регистрации в [app.main](../../../backend/app/main.py) формирует безопасный состав ответа. Автотест проверяет 17 вариантов обязательности полей, неверных типов, email, пароля и подтверждения. Отдельный вариант без username описан в [TC-AUTH-REG-004-01](../test-cases/TC-AUTH-REG-004-01.md).

## Границы проверки и дальнейшие задачи

Подтверждена защита ответа регистрации. Отсутствие чувствительных данных в журналировании и ошибках входа или других маршрутов требует отдельных проверок. Согласование формата остальных auth-ошибок указано в [QA-SEC-002](../findings.md#qa-sec-002).
