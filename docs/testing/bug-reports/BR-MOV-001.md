# BR-MOV-001 — Длина поиска проверяется до удаления пробелов

| Поле | Значение |
|---|---|
| Дата обнаружения | 14.11.2026 |
| Статус | Новый, исправление не выполнено |
| Компонент | `GET /movies/search`, параметр q |
| Основание | [API-контракт](../../api.md#поиск-и-открытие-фильма): q после удаления пробелов содержит 1–200 символов |
| Версия | `6417a7c` плюс новые тесты в рабочей копии, ветка `feature/auth-qa-tests` |
| Автотест | `test_search_validates_length_after_trimming`, MOV-SEARCH-004 |

## Воспроизведение

1. Подготовить q как один пробел, 200 символов `a` и ещё один пробел: `" " + "a" * 200 + " "`.
2. Отправить `GET /movies/search` с этим параметром. В автотесте MockTransport готов вернуть корректную пустую выдачу TMDB.
3. Проверить статус ответа и факт обращения к TMDB.

Фактически получен **422**. Запрос отклоняется валидацией Query до вызова адаптера TMDB.

Ожидается **200** с подготовленной выдачей TMDB: после обрезки q содержит ровно 200 символов. В TMDB должно передаваться значение без пробелов по краям.

## Причина и проверка

`app/api/movies.py` задаёт `Query(max_length=200)` для исходной строки. `strip()` в адаптере выполняется позднее и не достигается для входа длиной 202.

Отдельный запуск теста 14.11.2026 подтвердил `assert 422 == 200`. После воспроизведения тест отмечен `xfail(strict=True, raises=AssertionError)` со ссылкой на этот баг. Код приложения не изменялся.

После исправления убрать xfail и проверить длину нормализованной строки 1, 200 и 201, пробельный ввод, а также передачу обрезанного q в TMDB.
