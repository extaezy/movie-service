# BR-MOV-001 — Длина поиска проверяется до удаления пробелов

| Поле | Значение |
|---|---|
| Статус | Исправлен |
| Компонент | `GET /movies/search`, параметр q |
| Основание | [API-контракт](../../api.md#поиск-и-открытие-фильма): q после удаления пробелов содержит 1–200 символов |
| Автотест | `test_search_validates_length_after_trimming` в [тестах API фильмов](../../../backend/tests/test_movies_api.py) |

## Воспроизведение

1. Подготовить q как один пробел, 200 символов `a` и ещё один пробел: `" " + "a" * 200 + " "`.
2. Отправить `GET /movies/search` с этим параметром. MockTransport в тесте возвращает корректную пустую выдачу TMDB.
3. Проверить статус ответа и факт обращения к TMDB.

До исправления — `422`: исходная строка отклонялась до обращения к TMDB.

Ожидаемый результат — `200` с подготовленной выдачей: после обрезки q содержит ровно 200 символов, в TMDB передаётся значение без пробелов по краям.

## Причина

[Маршрут поиска](../../../backend/app/api/movies.py) ранее задавал `Query(max_length=200)` для исходной строки. `strip()` в адаптере выполнялся позднее и не достигался для входа длиной 202.

У существующей регрессионной проверки удалена отметка `xfail`: сценарий должен проходить как обычный тест.

## Исправление

Параметр q использует `StringConstraints(strip_whitespace=True, min_length=1, max_length=200)`: сначала удаляются пробелы по краям, затем проверяется длина. В адаптер передаётся нормализованное значение. Границы 1, 200, 201 символ, пробельный ввод и значение внешнего запроса проверяются при верификации исправления.
