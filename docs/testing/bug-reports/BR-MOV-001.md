# BR-MOV-001 — Длина поиска проверяется до удаления пробелов

| Поле | Значение |
|---|---|
| Статус | Открыт, исправление требуется |
| Компонент | `GET /movies/search`, параметр q |
| Основание | [API-контракт](../../api.md#поиск-и-открытие-фильма): q после удаления пробелов содержит 1–200 символов |
| Автотест | `test_search_validates_length_after_trimming` в [тестах API фильмов](../../../backend/tests/test_movies_api.py) |

## Воспроизведение

1. Подготовить q как один пробел, 200 символов `a` и ещё один пробел: `" " + "a" * 200 + " "`.
2. Отправить `GET /movies/search` с этим параметром. MockTransport в тесте возвращает корректную пустую выдачу TMDB.
3. Проверить статус ответа и факт обращения к TMDB.

Фактический результат — `422`: исходная строка отклоняется до обращения к TMDB.

Ожидаемый результат — `200` с подготовленной выдачей: после обрезки q содержит ровно 200 символов, в TMDB передаётся значение без пробелов по краям.

## Причина

[Маршрут поиска](../../../backend/app/api/movies.py) задаёт `Query(max_length=200)` для исходной строки. `strip()` в адаптере выполняется позднее и не достигается для входа длиной 202.

Тест помечен `xfail(strict=True, raises=AssertionError)`. Этот статус фиксирует открытый дефект и не считается успешной проверкой требования.

## План исправления

Применять ограничение длины после удаления пробелов по краям. Проверить нормализованные строки длиной 1, 200 и 201 символ, пробельный ввод и передачу обрезанного q в TMDB. После исправления убрать xfail.
