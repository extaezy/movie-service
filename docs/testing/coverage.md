| NFR.REL.04, частично, и API | Учётная запись сохраняется после перезапуска backend | Хранение в PostgreSQL реализовано | AUTH-DATA-002 | T-AUTH-01 освобождает пул соединений. Перезапуск процесса и сохранность Docker volume этим тестом не проверяются |

Покрытие условий авторизации является частью проверки общесистемных NFR. Итог по целому NFR выставляется после проверки всех относящихся к нему модулей и окружений.

## Предварительные условия и вопросы

Риск перечисления учётных записей через ответы регистрации зафиксирован в [QA-SEC-001](findings.md#qa-sec-001). Статус — требуется решение команды. Результаты AUTH-REG-007 и AUTH-REG-008 по действующему контракту остаются «Пройдено».

Возврат введённых пароля и подтверждения в `detail[].input` ошибки регистрации зафиксирован в [QA-SEC-002](findings.md#qa-sec-002). Статус — требуется решение команды по составу ошибок валидации.

| Объект | Состояние | Дальнейшее действие |
|---|---|---|
| Ограничения паролей, подтверждение, границы identifier | Ожидания взяты из кода | Согласовать AUTH-Q-002, затем включить AUTH-P-001, AUTH-P-002, AUTH-P-003, AUTH-P-004 в критерии приёмки |
| Соответствие ID в RTM основным требованиям | Выявлено расхождение | Разобрать AUTH-Q-001 в рамках задачи №13 |
| Формат ошибок auth | Требует уточнения | Разобрать AUTH-Q-003 в рамках задачи №16 |
| Полный собственный профиль | Уточняется отдельно от `/auth/me` | Разобрать AUTH-Q-004 |
| Logout и отзыв JWT | Отложено | Разобрать AUTH-Q-005 и задачу №36 |
| NFR.PERF.01, NFR.PERF.02, NFR.PERF.03 | Численные критерии требуют согласования с командой | Определить нагрузку, данные и окружение перед планированием нагрузочного прогона |
| NFR.MAINT.03 | Порог покрытия кода 70% требует согласования с командой | Определить область измерения и принятый порог |

Точные формулировки вопросов находятся в чек-листе. Задачи уже существуют в GitHub.
