## Правило сортировки

Основание — [локальный каталог в API](../../api.md#локальный-каталог). Сначала сравнивается дата выхода в выбранном направлении. При одинаковой дате сравнивается внутренний ID по возрастанию. Фильмы без даты идут в конце в обоих направлениях, также по возрастанию ID.

Например, есть фильмы 7 и 9 с датой 2020-06-01, фильм 5 с датой 1999-01-01 и фильм 11 без даты:

| sort | Правильная последовательность ID |
|---|---|
| release_date_asc | 5, 7, 9, 11 |
| release_date_desc | 7, 9, 5, 11 |

Полное переворачивание первого списка не даёт второй: оно перевернёт порядок одинаковых дат и перенесёт неизвестную дату в начало.

## Три приёма для проверки

Пример 1: сложение списков соединяет их элементы с сохранением порядка.

```python
first_page_ids = [7, 9]
second_page_ids = [5, 11]
combined_ids = first_page_ids + second_page_ids
assert combined_ids == [7, 9, 5, 11]
```

Пример 2: множество убирает повторы. Сравнение размеров показывает наличие дублей, но не проверяет порядок и полноту.

```python
actual_ids = [7, 9, 9, 11]
assert len(actual_ids) == 4
assert len(set(actual_ids)) == 3
```

Оба assertion здесь проходят: первый считает все элементы, второй — уникальные. Для требования «без повторов» нужно сравнить эти два количества между собой. Список `[7, 11]` тоже не имеет повторов, хотя фильмы 9 и 5 потеряны. Поэтому дополнительно сравниваем полную последовательность с ожидаемой.

Пример 3: срез выделяет ожидаемые элементы каждой страницы. Левая граница включается, правая не включается; индексы начинаются с нуля.

```python
expected_ids = [7, 9, 5, 11]
page_size = 2
assert expected_ids[:page_size] == [7, 9]
assert expected_ids[page_size:] == [5, 11]
```

Для чтения ID из HTTP-ответа пригодится уже знакомое выражение `[movie["id"] for movie in response.json()["results"]`. Сначала проверяй `response.status_code`, затем разбирай JSON успешного ответа.

При размере страницы 20 ожидаются ID 1–20 на первой странице и 21–24 на второй. Для обоих направлений сортировки результат одинаков: все известные даты равны, а ID при равенстве возрастают.

## Задание

1. Получи первую и вторую страницы через `await client.get(endpoint, params=...)`.
2. Проверь статус каждого ответа. В обоих ответах проверь `page`, `page_size`, `total_results` и `total_pages`.
3. Извлеки ID из `results`. Сравни каждую страницу со своим ожидаемым списком.
4. Соедини фактические ID страниц и сравни с `expected_ids`. Отдельно проверь, что число уникальных ID равно числу полученных ID.
5. Ещё раз запроси первую страницу через тот же `client`; проверь 200 и равенство JSON первому ответу.
6. Проверь отсутствие запросов TMDB через `catalog_tmdb.upstream_requests`.

Здесь не нужно подменять репозиторий или писать SQL: подготовку данных выполняет фикстура. Запросы выполняй последовательно, чтобы каждый шаг было проще проверить.
